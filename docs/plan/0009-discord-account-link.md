## Risks
- Report submit latency: refresh + guilds + N member calls + M posts, 5 s timeout each, inside the request. Member route rate limit is strict; 429 skips, never sleeps.
- Concurrent refresh with one rotating token would falsely flag `needs_reconnect`; `FOR UPDATE` on the connection row serialises it. Lock held across one HTTP call.
- Key lost or changed → every link `needs_reconnect`. Owner backs the key up with the stack secrets.
- Release B before A's migration → `/users/me` reads a missing table → every page 500. Runbook order is the only guard.
- Rollback C = `alembic downgrade <S5 rev>` (renames back). Rollback B = previous image + `DISCORD_REPORTS_WEBHOOK` and `DISCORD_REPORTS_ORGANIZATION` still set; only after C is rolled back (pre-B code maps `is_org_member`). Rollback A = `alembic downgrade c1d9f4a7b3e6`: drops connections + webhooks. Order C → B → A.
- `is_org_member` goes stale from B on (no login writes it); C freezes it as `_old`. Accepted: nothing reads it.
- Discord may return fewer scopes than asked; `scopes` stored; routing without `guilds` treated as `needs_reconnect`.
- Transfer (R-008): whoever passes Discord consent as account X takes X's link from its Applika holder, no notice. Holder's refresh token dropped unrevoked; X's one Discord authorisation for the app now serves the new holder.
