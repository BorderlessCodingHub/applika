AC:
- The system stores each application's progress as timeline events of exactly one type: note, interview, feedback, offer or denied.
- The system stores an interview type on interview events only, from the fixed list unknown, initial screening, technical, cultural, hiring manager, take-home and final, defaulting to unknown.
- The system refuses an interview type on any event that is not an interview.
- The system stores an event date, an optional start and end time given together with the end after the start, an optional timezone and an optional observation on every event.
- The system requires salary amount, currency and period on offer events and refuses them on every other event.
- The system lets a user list, add, replace and delete the events of their own application.
- The system closes an application on finalize without asking for a step, feedback or salary, and records when it was closed.
- The system reopens a closed application on request and makes it editable again.
- The system treats finalizing a closed application and reopening an open one as no-ops, not errors.
- The system refuses event changes on a closed application as a conflict that tells the user to reopen it.
- The system refuses event changes, finalize and reopen on an application archived in a cycle as a business-rule violation, as it does today.
- The system no longer couples an Offer step to an Accepted feedback.
- The system shows every step that existed before the switch as a timeline event with its date, times, timezone and observation, and keeps its identifier.
